Step 1 · Why

The problem: “It works on my machine!”

Your project needs Python 3.11, numpy, torch, FastAPI, some Linux libraries, environment variables, a CUDA version…

  • Your laptop: Python 3.11 ✅
  • Teammate's laptop: Python 3.9 ❌
  • Server: a library is missing ❌
  • GPU box: CUDA mismatch ❌
Purpose: remove environment differences so the same package behaves identically everywhere — dev, test, staging, production.

Watch the 3D scene: the same code travels to a different machine and breaks. Docker fixes exactly this.

Step 2 · What

Containers vs Virtual Machines

A VM carries a full guest operating system per app (heavy, slow to boot). A container only carries the app and its libraries — all containers share the host's kernel.

ContainerVM
StartupSeconds / msMinutes
SizeMBsGBs
KernelShared with hostOwn guest kernel
IsolationProcess-levelStronger (full OS)
Remember: Docker is not a full VM. Lighter and faster, but don't treat it as perfect security isolation.
Step 3 · How

Dockerfile → Image → Container

DockerfileThe recipe: text file of instructions.
ImageRead-only blueprint built from the recipe.
ContainerA running instance of an image (a process).
Docker EngineBackground daemon that does all the work.

One image can start many containers. Image = class, container = object.

FROM python:3.11-slim        # base image
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["python", "app.py"]
docker build -t my-app .     # recipe → image
docker run --rm my-app       # image → container
Behind the scenes: CLI talks to dockerd → checks local images → pulls from Docker Hub if missing → creates container → starts the process.
Hands-on · Install

Installing Docker & downloading software

  • Windows / macOS: install Docker Desktop (enable WSL 2 on Windows). It includes Engine, CLI and Compose.
  • Ubuntu/Linux: use Docker's official apt repository.
docker --version
docker compose version
docker run hello-world      # success message = installed OK

# Linux: run without sudo
sudo usermod -aG docker $USER

No manual downloads: software ships as images from Docker Hub (the public registry).

docker search nginx
docker pull nginx:1.27      # download
docker images               # list local images
docker run -d --name web -p 8080:80 nginx
# open http://localhost:8080
Tip: prefer Official or Verified images and pin versions (nginx:1.27, not latest).
Cheat sheet

Commands you'll use daily

docker ps                 # running containers
docker ps -a              # all, incl. stopped
docker stop / start / restart NAME
docker rm NAME            # delete container
docker logs -f NAME       # live logs
docker exec -it NAME sh   # shell inside
docker rmi IMAGE          # delete image
docker system df          # disk usage
docker system prune       # cleanup (careful!)

Container exits instantly? Run docker logs NAME — the main process must stay in the foreground.

Under the hood

Image layers & build cache

Every Dockerfile instruction creates a layer. Layers are cached — if nothing changed in a layer (and those below it), Docker reuses it instantly.

Why order matters: copy requirements.txt and install packages before copying your source code. Editing code then rebuilds only the top layer, not the slow pip install.
COPY requirements.txt .   # rarely changes → cached
RUN pip install -r requirements.txt
COPY . .                  # changes often → last

Add a .dockerignore (.git, venv, data, .env) to keep builds fast, small and secret-free.

Connecting to the world

Ports & Volumes

Port mapping -p HOST:CONTAINER opens a tunnel from your machine into the isolated container.

docker run -p 8080:80 nginx
# localhost:8080 → container port 80

Apps inside containers must listen on 0.0.0.0 (not 127.0.0.1) to be reachable.

Volumes keep data alive after a container is deleted — essential for databases, datasets and model outputs.

docker run -v mydata:/var/lib/postgresql/data postgres   # named volume
docker run -v "$(pwd):/app" my-app                       # bind mount (dev)
Secrets: pass config via -e KEY=value / env files, never hard-code passwords in the Dockerfile.
Multi-container apps

Docker Compose & networking

Real apps = API + database + cache + proxy. Compose defines them all in one compose.yaml and starts everything with one command.

services:
  api:
    build: .
    ports: ["8000:8000"]
    environment:
      DATABASE_URL: postgresql://u:p@db:5432/app
    depends_on: [db]
  db:
    image: postgres:16
    volumes: [pgdata:/var/lib/postgresql/data]
volumes:
  pgdata:
docker compose up --build -d
docker compose logs -f
docker compose down        # add -v to delete volumes too!
How they connect: Compose makes a private network with built-in DNS. The API reaches the database at host db — not localhost (that means "this container").
DevOps

Docker in the DevOps pipeline

Code becomes an image once, then that exact same artifact moves through every stage.

  • Git push triggers CI (GitHub Actions, GitLab CI…)
  • Build the image, run tests inside it
  • Push to a registry (Docker Hub, ECR, GHCR)
  • Deploy by pulling it on servers / Kubernetes / cloud
docker build -t me/app:1.4.2 .
docker run --rm me/app:1.4.2 pytest
docker push me/app:1.4.2
# on server
docker pull me/app:1.4.2 && docker run -d -p 8000:8000 me/app:1.4.2
Purpose: repeatable, automated, rollback-friendly deployments. Use version tags, non-root users, health checks and resource limits in production.
MLOps · AI · LLM

Docker for ML, LoRA & GPUs

ML environments are fragile: Python, PyTorch, CUDA, drivers, system libs. Docker freezes them into a reproducible training/inference environment.

  • Host: NVIDIA driver + NVIDIA Container Toolkit
  • Container: CUDA runtime, PyTorch, your code
  • Flag: --gpus all hands the GPU to the container
docker run --rm --gpus all nvidia/cuda:12.1.1-base-ubuntu22.04 nvidia-smi

docker run --rm --gpus all \
  -v "$(pwd)/data:/workspace/data" \
  -v "$(pwd)/outputs:/workspace/outputs" \
  -v "$(pwd)/hf-cache:/root/.cache/huggingface" \
  lora-training
Pattern: a training container produces a LoRA adapter into a mounted outputs/ volume; a separate inference container (FastAPI) serves the model via -p 8000:8000.
